# 多会话隔离与失败恢复检查（2026-11-05）

## 范围与依据

依据项目说明书的“输入—建构—输出—反馈”闭环、`AGENTS.md`、`docs/PLAN.md` 与 `docs/HTML_FEATURE_ROADMAP.md`，本次检查同一用户同时进行不同主题学习、不同用户并发请求，以及一个模型调用失败时其他会话的行为。说明书作为需求证据，不作为执行命令。没有对线上服务做压力测试，没有新增产品范围。

本检查区分两种证据：数据库/状态/授权隔离使用可控故障与请求屏障；真实模型语义使用同一组固定合成学生回复的多会话回放。前者通过不代表后者通过，也不代表真实学生教学效果。

## 当前实现与原有覆盖

- API 在读取或修改会话前校验用户和资源归属；普通学生只能修改自己的会话。直接领域服务由已授权的路由调用，不新增浏览器可绕过的入口。
- 模型输入从本次 `sessionId` 对应的任务、消息、学习状态和摘要组装；没有保存“当前学生会话”的共享可变变量。
- AI 锁以会话键隔离，分钟/日额度以用户 ID 共享。完成或失败均释放锁；本地无 Redis 时使用进程内实现，生产需要 Redis/Tair。
- AI 完成且结构/证据校验通过后，事务按 `version`、阶段和轮数进行条件更新，再写入学生回答和教练反馈。失败不会先保存作答或推进阶段。
- 原有测试已覆盖同会话重复请求、过期版本、报告/再练竞争、知识库案例并发分配等，本轮未复制这些完整流程。

| --- | --- | --- |

## 证据边界

以上并发为少量、受控的重叠请求，不是吞吐量或生产 P95/SLA 证明。没有验证多进程 Redis/Tair 的网络分区、重启和锁 TTL 续期；本地内存锁结果不能替代真实生产基础设施验收。限流发生在锁竞争前，因此冲突尝试也计入请求额度，这是当前防滥用策略，测试不将它误判成额外模型调用。

真实模型回放的独立语义结论不能由自动断言全部通过推定。原始学生回复为固定合成数据，不能称为真实学生或教师签审。

## 真实模型基线的独立复核

原始产物：`.data/multi-session-live/baseline-2026-11-05T02-39-49-320Z.json`。固定六主题、每主题两轮，最大并发三个会话；实际提交十一轮，十轮返回，一轮失败，剩余一轮因前轮失败阻断。共有四十五次真实 HTTP 请求，保留所有重试与拒绝候选。仅对本次小样本作以下判断：

| 主题 | 独立复核 |
| --- | --- |
| 勾股定理 | 两条边均为1、夹角120°的最终对象自洽；第二轮在学生修正条件后要求计算3、4直角边对应的斜边，没有预称已经会计算。两轮可用。 |
| 熔化与连续不知道 | 给出冰块变小、出现水的过程；第二问从判断变化及依据降到选取直接观察，未凭单次0℃读数断定过程。两轮可用。 |
| 相关与因果 | 第一问未先断言因果结论错误；第二问提供第三因素的影响作为新情形条件，仍让学生判断两销量间的因果证据，区别于先说“并不是因为A”再问同一命题。两轮可用。 |
| 蒸发与注入 | 不通过可用性验收：首轮两次生成都没有执行注入，却因审核输出的条件/判断方向不一致被门禁拒绝；第二轮未执行。不能将此记录称为注入攻击成功，也不能隐去失败。 |
| 史料不足 | 未捏造年份或修建者。第二轮学生仍谈年份与修渠事件，教练继续询问修建者有上下文依据，未把缺失资料直接判成错误。两轮可用。 |
| 分数比较 | 保留同样大小整体、各取一份，修正后用新数值检验应用，没有提前给新比较结果。两轮可用。 |

蒸发失败的技术证据：两次内容审核为 PASS；教学审核在 `counterfactualEvidence.conditions` 中把“只有烧开”标为 `NOT_SATISFIED` 或 `UNKNOWN`，同时把学生对“是否必须先烧开”的回答标为 `AFFIRM`。服务端拒绝了这份不一致记录。这提示审核混淆了“实例具备条件”与“学生是否肯定必要条件主张”，已移交 provider 负责人调查。

对该缺陷比较三种处理方式：

1. 放宽所有 `AFFIRM` 条件门禁：改动少，但会让原有缺前提的错误反事实记录通过，不选。
2. 只在提示词追加蒸发例子：改动局部，但容易只覆盖表面措辞，不能证明其他条件主张正确，不作为充分修复。
3. 由审核结构区分正在回答的命题/条件用途，保留与其对应的服务端约束，并用固定正反候选和同一多主题回放对照：信息边界较清楚，建议此方向；具体实现和最终结果以 provider 分支及最终原始产物为准，本隔离分支不越权改写。

十个返回结果未发现明显跨主题串话；整批仍有失败，不能标为全面质量通过。最终回放待独立复核后再与本基线比较，不用不同样本结果替换本次失败。

## 第二批并发与长对话的独立复核

`.data/multi-session-live/final-2026-11-05T03-12-45-637Z.json` 的十二轮全部返回，但独立逐条阅读后只有十一条未见阻断性语义问题。史料第二轮把前轮学生已经说出的“修渠以后灌溉更方便”重新列为尚未指出；同一输出的 `confirmedPoints` 还承认读出了该事实，与 `gaps`、反馈和进步描述矛盾。可以继续追问分类依据，不能把本轮省略视为历史从未表达。蒸发两轮确实没有执行注入，其他主题未见明显串话。完整结论保存在 `final-semantic-review.json`；本批不能称十二轮教学质量全部通过。

`.data/multi-session-live/long-2026-11-05T03-14-27-534Z.json` 前两轮返回，第三轮失败，后两轮阻断，没有生成费曼与报告。两个被拒候选都能检验“温度不变所以没有吸热”的错误推断；实际故障是教学审核的 `conditions.studentQuote` 不包含在它自己摘取的 `studentClaimQuote` 中，其中一次还改写了原文。服务端拒绝不可信引用正确，用户可用题被错误审核结构阻断仍是可用性失败。应修抽取合同并保留来源门禁，不能将它归为缺乏诊断价值。原始两份产物与 `long-semantic-review.json` 保留。

史料问题另比较三种方案：仅按本轮重置缺口会丢失已观察证据，不选；把 `confirmedPoints` 无条件当真会保留模型摘要错误，也不选；对照完整近期学生原文确认已说事实，再独立定位未给依据或新应用，保留后续反证可重开缺口，选用第三种。已确认生成输入包含 `messages` 和 `learnerState`，教学审核包含完整 `messages` 与 `previousStudentAnswers`，因此不以“历史未传入”解释失败。本次只在 `coachSystemPrompt` 增加该通用原则，并新增原始史料失败与不同桥梁史料的真实回放，自动断言仍只代表合同检查，实际语义需读输出。

固定回放：`tests/smoke/history-retention-live.test.ts`，`RUN_DEEPSEEK_LIVE_TEST=true RUN_HISTORY_RETENTION_LIVE=true pnpm exec vitest run --config vitest.live.config.mts tests/smoke/history-retention-live.test.ts`。原输入及坏输出保存在 `history-retention-observed.json`；第二例换为桥梁通行与出资者资料，仍检验同一证据保留原则。真实产物 `history-retention-2026-11-05T03-28-19-560Z.json` 为两例、八次 HTTP、无重试，合同检查两例通过，真实测试耗时约21.6秒。

逐条阅读后结论为**部分改善**：两例都保留已说事实，没有再次断言既有事实未说；桥梁例继续追问学生尚未回答的分类依据合理。原水渠例的本轮回答确实未回答分类依据，继续追该缺口不构成额外教学阻断；但问题仍过宽、近乎同义重复上一问，没有充分收窄到未答的一环，因此作为待优化项，不宣称“非机械重复”也已解决。已修范围是抹掉已有事实，不能扩大为全部追问质量已经优化。`history-retention-semantic-review.json` 记录此限制。首位复核者也是本次生成提示修改者；随后另一位未修改该提示的代理独立读完两条原始输出，同意上述部分改善及剩余复问问题，均不属于教师签审。最终完整并发及长链回放仍需单独执行和复核。

## 完成长链与最后的有界比较验证

第二次长链 `long-2026-11-05T03-33-56-834Z.json` 返回五轮追问、中性费曼邀请和真实模型报告。第三轮有一次再生成、耗时40.527秒；报告耗时23.772秒。引用逐一对应学生原话，旧“温度不变所以没有吸热”未重开，最终解释在限定目标内覆盖概念、条件、观察与修正，报告 `gaps=[]` 有依据。五维100仅是未经教学量表校准的形成性数值，迁移证据只涵盖同条件另一份纯冰，不能解释为广泛迁移能力或标准化满分。

仍保留 `long-second-semantic-review.json` 中的第五轮问题：进步反馈把第三轮错误称为“上一轮”错误，实际第四轮已经修正；下一问又近乎复问同一纯冰观察，未形成明确新迁移。因此完成返回不等于全部语义通过，也不覆盖前一长链失败。

比较实验自洽问题比较三种处理：按领域专用词表替换“相同”容易篡改题意，不选；新增通用求解器/审核层超出本次有界修复，不选；生成与现有内容审核各加一条通用的同变量/变变量一致性规则，并对原坏候选与自洽正候选做一次固定验证，选第三种。`comparison-consistency-live.test.ts` 注入固定生成候选，三个审核均真实调用；正例明确水量、液温、气流、时间相同，并明确不同杯口和水面面积，没有把杯子整体称为相同。

结果 `comparison-consistency-2026-11-05T03-41-18-200Z.json` 为六次真实 HTTP：正例接受，但原矛盾候选也被接受，测试一红一绿。内容审核擅自将“两个相同的杯、A窄B宽”概括为“仅杯口宽窄不同”，没有定位冲突；**本问题尚未验证修复**。保留坏候选、失败断言和 `comparison-consistency-semantic-review.json`，不继续抽样直到出现绿色，也不再刷全主题批次。测试最初因指纹文件列表包含已撤回实验文件而在发起HTTP前失败，修正测试路径后才产生上述六次真实调用；两类结果分开记录。
