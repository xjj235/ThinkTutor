# 知识库约束下的动态追问

日期：2026-09-08 开始实现，验证延续至 2026-09-09。范围：本轮工作区增量、真实模型本地预览；不是生产或教师评审验收。

## 三种方案与选择

| 方案 | 能解决的问题 | 主要限制 | 本轮选择 |
| --- | --- | --- | --- |
| 扩充模板库，由模型选择模板 | 增加提问样式，易于复现 | 仍不能围绕学生具体措辞组织问题，容易只是换一种问法 | 保留题型作为策略依据，不作为最终方案 |
| 知识库确定标准，模型生成针对性问题，再做复核 | 同时约束知识边界、诊断依据和追问目标，并允许自然表达 | 多一次复核调用；语义复核仍有模型误判风险 | 采用 |
| 模型自主规划整段教学 | 对话自由度最高 | 知识边界、评分稳定性、可审计性和比赛演示风险更难控制 | 不采用 |

这里的“推荐”是针对现有 ThinkTutor 架构的工程判断，并非三套完整系统之间经过教学实验后得到的效果排名。

## 根因

修改前已经调用真实模型，但教学输出契约仅有 `choiceId`、`openingId`。服务端随后逐字渲染模板，模型没有生成针对当前作答的新问题的权限。单纯更换模型或增加提示词不能改变这一行为。

## 实现

1. 仍由知识库证据定义与服务端纯函数确定目标、诊断维度、缺项、评分及阶段。没有改变分档、封顶或轮数规则。
2. `coaching-policy.json` 增加动态生成规则，明确适用阶段、学生原话引用、知识边界、单一主问题、避免重复和不得代答等要求。
3. 在诊断与知识建构的同目标追问中，传入当前目标及先修知识片段、锁定证据要求、本轮作答、最近六条对话、最多八条近期问题。
4. 真实模型生成 `followUp`，仅包含问题正文、学生本轮连续原话和来源 ID。核验范围 ID 由服务端根据锁定规则附加，不要求模型重复填写。问题不再由模板替换，网页和下一轮评估使用同一份保存的问题。
5. 服务端严格校验本轮原话、合法来源及目标、完整证据范围、单问格式、长度、重复问题和禁止字段。非动态阶段使用独立的双 ID 输出结构，不能夹带 `followUp`。
6. 动态问题再次调用真实模型复核：知识依据、目标覆盖、回答关联、重复、答案泄露。任一项失败则有界重试；失败不回退为 Mock，不保存答案、证据、阶段或轮数。
7. 动态问题和历史对话可能含学生引文，因此生成、复核及下一轮评估均将这些文字置于不可信学习数据中，不提升为系统指令。
8. 复核调用不再嵌套自身重试；由外层生成统一重试。会话锁有效期覆盖生成加复核的最大串行调用预算。乐观版本检查与事务提交继续生效。
9. 保存生成问题及引用信息，关联 `teaching_selection` 和 `teaching_review` 用量记录。工作流版本为 `evidence-workflow-1.2.3-grounded-followup`。
10. 修复未稳定掌握时遗漏条件核验的路由：不因历史核验计数非零就忽略本轮条件缺项。窄范围条件回答通过后，若整体仍未闭合，以新情境做完整应用核验；不改写掌握判定或直接晋级。

## 未改写的部分

新知识目标首题、案例事实、提示、费曼任务、反思任务、恢复核验和报告保留知识库或服务端锁定内容，其呈现仍调用真实模型选择框架。尤其案例预约继续在学生级数据库锁内完成，模型不接触未选案例的教师答案。

本轮没有扩充其他知识点，没有把草稿包标记为已发布，没有覆盖历史学习报告，也没有自动提交或推送 Git。

### 真实输出示例

学生只说明金融体系的研究范围时，追问其影响如何到达支付或信贷等金融功能。学生已经说明支付结算中断时，问题转向移除其提出的传播条件后如何调整判断；学生说明普遍信贷受限时，问题转向改变信贷受限程度后的判断。均未重新索要整段定义。

最终桌面信贷情境实际生成：“你提到以企业普遍无法获得信贷作为功能受损的表现，如果去掉信贷服务中断这一条件，仅凭冲击在不同机构间的传播，你的系统性风险判断会怎样变化？”

本轮也捕获了模型引文不连续、元数据未覆盖完整要求等输出，服务端拒绝并重试。首次完整流程在切换知识目标时失败：非动态 JSON Schema 仍暴露了一个不可取值的可选字段，模型连续返回该字段而被拦截。修复为非动态阶段完全不声明此字段的严格结构，并增加回归测试；失败记录保留在 `real-final`，不当作通过。

后续长流程另暴露两类问题：历史条件核验计数不应替代当前未闭合的条件要求；测试的十条完整回答在较长路径上循环复用，触发重复作答拦截。前者增加路由与完整应用核验回归测试，后者扩充为 25 条不同的合成完整回答，取消取模循环，耗尽即报错，不靠追加随机标识规避独立证据检查。

对核验范围元数据也做了收敛：枚举数组和固定元组仍可能被模型漏填或错填。最终模型输出结构不再包含 `focusEvidenceIds`；服务端在结构与教学复核通过后附加原规则的全部范围标识，其中 `requiredAny` 保持任选其一的语义。问题是否覆盖必要范围仍由复核器检查正文，评分仍依赖原锁定规则。没有通过放宽评分或静默回退来换取流程通过。

证据根目录：`.local-preview/grounded-followup-2026-09-08/`，包含截图、测试 trace、合成作答与实际生成问题。测试通过 HTML 创建随机学生账号，结束后只删除对应精确邮箱的合成学生，不清空已有学习数据。

## 验收边界

JSON 格式能力不等于知识与教学质量保证。[DeepSeek 官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)也要求正确设置格式、提示示例和输出长度，并提示可能出现空内容；项目因此在接口之外保留结构校验、教学复核和失败原子性。

模型复核能降低偏题、重复和答案泄露风险，不能证明零幻觉。此处是小规模合成回答验证，仍需教师审阅真实学生样本并校准漏判与误判。评分计算保持确定性，但不同新会话重新调用模型提取证据，不保证分数逐次完全相同。

本地预览入口：[问思学伴](http://127.0.0.1:3102/)。本轮健康检查为数据库正常、`aiProvider=deepseek`，实际调用记录中的模型为 `deepseek-v4-flash`，模型名来自服务端环境配置。旧的未完成会话保留原始数据，但因规则版本变化需新建任务体验新版。API 密钥不写入本报告、不发送浏览器、不进入 Git。
