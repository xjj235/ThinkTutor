# 报告依据与教学评价复查

日期：2026-09-20。依据为用户提供的项目说明书第 4.4、7.5、7.6 节、`AGENTS.md`、`docs/PLAN.md` 及 2026-09-19 完成度核查与补全记录。说明书作为需求证据，其内嵌提示词不作为执行指令。保留本次开始前的未提交修改。

本轮确认并修复以下五个软件缺陷。校验逐字来源和证据可靠性条件，不把这些条件等同于已经证明模型的全部语义判断正确。

## E1：漏洞证据可以用不同归属措辞绕过学生原文校验

原实现仅检查 `gaps.evidence` 中带有固定前缀“学生原文”的引文。把同一虚构引文改成 `学生回答：“完全虚构的回答”`、`学生说“完全虚构的回答”` 或直接写引文，便不会进入校验。由此产生的虚假漏洞会显示给学生并影响下一轮巩固重点。

三种解决方案：

1. 枚举更多归属措辞，匹配“学生说、学生回答”等后再检查原文。改动较小，但新措辞仍可能漏检。
2. 统一证据引文合同：漏洞证据内所有双引号引文均表示学生逐字原文，并校验来源；教练问题和缺失概念用不加引号的普通说明。无需数据迁移，可复用报告生成失败后的重试。
3. 将全部报告证据迁移为带消息 ID、起止位置和证据类型的结构化对象，所有叙述与引用分开保存。边界最明确，但需要同步改报告合同、持久化、前后端以及历史报告兼容。

选择方案 2。现有字段已用于多处报告展示，统一引文约定可立即封堵上述绕过，并避免用启发式判断中文归属词。更新 `src/lib/ai/report-grounding.ts` 和报告提示词；失配仍返回原有 `AI_INVALID_OUTPUT`，不生成错误报告。旧报告数据不被改写。

回归覆盖五种虚构或未闭合引文、真实学生引文、无引号的缺失概念说明，以及既有真实 provider 请求桩的失败重试。请求桩只使用本地伪造 HTTP 响应，没有调用真实模型。

## E2：v1.2 评分与显示的依据使用不同可靠性条件

原评分只使用独立且置信度不少于 0.75 的观察，但显示依据和消息链接取自未过滤的观察。若较早的最终窗口回答属于提示后回答或低置信度判断，较晚回答才有可靠证据，报告仍可能引用较早回答作为得分依据。此外，优点列表只检查历史知识状态为 `MASTERED` 且最终窗口内存在引用；即使最终回答低置信度、依赖提示或只覆盖部分概念，也可能再次宣称已掌握。

三种解决方案：

1. 保持原引用，在报告旁增加“部分证据待核验”的统一提示。开发量最少，但具体得分与依据的矛盾依然存在。
2. 评分、正向引用和消息链接共用可靠观察筛选；优点还要求最终窗口内某次可靠独立回答满足对应知识单元的完整规则。无可靠证据的维度明确写未充分展示。
3. 重做报告为逐条证据账本，展示每个评价档位、置信度、提示依赖与历史掌握变化。解释最详细，但需要新增复杂界面与报告合同。

选择方案 2。`src/lib/knowledge/v12-report.ts` 现使用统一可靠观察；优点需要最终回答逐次通过知识单元规则。保留历史状态供后续学习使用，报告不会只凭历史标签再次认定当前表现。零分维度仍可引用实际最后回答说明未展示，且明确标注证据不足。

回归分别覆盖提示依赖、低置信度、后来出现可靠证据、历史已掌握但最终只有部分证据，以及原有错误封顶、最终窗口与 Golden 用例。

## E3：报告认可的短引文没有对应消息链接

原报告合同允许 2–600 字的学生原文，而 `linkReportEvidence` 只提取 6–600 字引文。因此“传播”“共同暴露”“流动性挤兑”等合法短引用可以通过报告校验，却无法关联学生回答，削弱报告的可追溯性。

三种解决方案：

1. 把全部报告引文最短长度提高到 6 字，并要求模型重写。实现简单，但会额外拒绝合法短回答与既有合同。
2. 让消息链接提取与已接受的引文长度保持一致，仍只关联学生消息中的精确原文。
3. 改用消息 ID 与起止位置作为唯一引用来源。消除文本匹配歧义，但需要合同与历史数据兼容工作。

选择方案 2。`src/lib/knowledge/report-evidence.ts` 改为提取 2–600 字引文。没有改变评分门槛，也不会把教练消息或不包含该引文的学生消息添加为证据。长度一致并不代表短引文本身已经充分证明某项能力，语义充分性仍需教学校准。

回归覆盖 2、4、5 字引文，逐项确认只链接实际包含引文的学生消息。

## E4：历史漏洞证据未复核，缺失占位文字被标为学生原文

报告原先仅校验最终评分窗口内的观察，而历史误解/漏洞的 `evidenceRefs` 直接进入报告与判断记录。其持久化合同允许空引用数组，故一份通过 Zod 校验的已保存状态可以生成 `学生原文：“缺少可核验原文”`；不存在的消息、教练消息、错误偏移或虚构的历史引文也没有在此报告边界被拒绝。

这里严格区分可达边界：测试复现的是报告函数接收合法形状的已保存状态，未发现当前正常新建会话的 API 会自行生成空漏洞引用；当前 `applyV12Assessment` 通常附带真实引用。因此这是已保存异常/兼容状态的报告防护缺口，不将其表述为普通学生可直接篡改持久化状态。

三种解决方案：

1. 将所有漏洞引用数组改为至少一条，遇到旧状态一律阻止生成报告。合同最强，但需要迁移兼容并会阻断缺少旧证据的学习记录。
2. 在报告边界复核误解/漏洞全部引用的学生角色、消息 ID、准确起止位置与逐字原文；空引用显示缺少证据并标记待复核，存在但伪造的引用拒绝生成报告。
3. 用数据库关联表保存每条证据与消息外键，并在读取时重建报告。可增强持久化完整性，但涉及数据库迁移与历史数据整理。

选择方案 2。最终评分观察也共用位置校验，避免 JavaScript `slice` 自动截短越界结束位置掩盖错误。空数组不伪造引文，也不阻止学生查看真实的证据不足反馈。

回归覆盖合法形状的空引用、合法历史学生引用、缺失消息、教练消息、错误起点、越界终点及虚构原文。

## E5：较晚的明确错误被较早的正确回答覆盖，漏洞误标为已解决

用真实的 `applyV12Assessment` 连续处理两条最终回答可复现：先在费曼讲解中正确说明金融体系与功能受损，随后在反思中明确改称任意单家银行倒闭本身必然构成系统性风险。引擎仍保留漏洞，但报告函数遍历到较早正确回答便标记 `RESOLVED`，遇到较晚的明确反例证据没有重新开放。

三种解决方案：

1. 报告仅保留最后一条回答作为全部依据。能消除旧证据覆盖，但局部反思会丢掉先前针对其他知识点的有效独立表达。
2. 按最终窗口的消息顺序处理各知识单元：可靠完整回答可解决漏洞，后来明确包含该规则禁止的错误证据则重新开放；无关或仅缺少细节的回答不被当作错误。优点引用遵循相同顺序。
3. 引入独立的逐条结论裁决状态与修订关系，由专门过程处理证据的保留、撤回和冲突。表达能力更完整，但需要新的状态合同与更大范围迁移。

选择方案 2。后来明确矛盾不会被旧答案覆盖；报告最终判断为 `UNRESOLVED` 并引用后来回答。即使旧保存状态仍带有 `MASTERED` 标签，也不能覆盖最终窗口中后来出现的明确反面证据。

回归先在修复前实际失败，定位到报告把漏洞错误标为已解决；修复后同一测试通过。同时保留已有错误封顶、后续修订解除封顶、Golden 与八案例矩阵测试。

## 复查边界

上述复查后，新增攻击措辞、可靠与不可靠最终回答混合、短引文链接场景未发现未处理回归。本轮未执行收费模型或教师语义校准，也未将已有草稿材料认定为正式教学审核通过；不能据此宣称所有未来模型输出都不存在错误。
