# 独立短答案暴露审核实验（2026-11-05）

## 决策范围

对既有内容审核曾漏检的“先给因果否定、再问同一判断”，比较三种方式：继续扩充综合提示词、所有内容审核开启推理、独立短审核与内容审核并行。综合提示词已有漏检；全量推理在此前固定候选出现9–34秒及截断/结构失败。本实验选择第三种方式，限定只审答案暴露，不判断题设数学相容性，不替代原有门禁。

新增模块 `src/lib/ai/answer-disclosure-audit.ts`，尚未由本实验直接接入 provider。模块提供输入构造、Zod 输出合同和服务端结果验证。是否接入须通过组合候选与并行墙钟核验；单模块仍有已知漏检，不能宣称单独可靠覆盖全部问题。

## 输入与验证

输入包含学生实际表达及五个固定字段：`question`、`observation`、`focus`、`whyItMatters`、`progress`。学生引文 `answerQuote` 不作为教练陈述扫描。全部内容放在不可信用户数据边界，固定指令与字段标识由服务端定义。

输出必须覆盖五个 ID 各一次，逐字定位实际问题和有风险字段；不允许用整段待答问句冒充已断言答案。服务端拒绝无来源引文、重复字段、缺失字段和不确定结果。第二版额外将“预设当前判断需要纠正”和“对象名称已给待识别属性”分别定位，避免综合 OPEN 标签掩盖具体风险。语义分类仍由模型完成，字段齐全不等于分类正确。

## 真实模型固定样例

九个候选各重复两次，均为真实 `deepseek-v4-flash` HTTP 审核，串行、无重试，`thinking=disabled`、`temperature=0`、`max_tokens=1000`。不生成新的学生或教练候选，不接生产数据库，不进行线上压力测试。

负例：直接给因果否定、暗示待判断推断需要修正、定义性名词含待识别角条件、反馈先给新计算结果。正例：中性观测题设、学生已知方向后寻找共同因素、给公式求新值、回顾已知规则后用于新比较、学生注入指令被当作数据。

| 第二版：明确两种具体预设 | 15/18严格通过；定义名词漏一次；两次正确识别因果暴露但多输出解释字段导致结构失败；正例10/10通过 | 1444 / 2161 / 3909 ms |

## 组合门槛与工程检查

若既有内容/教学审核能稳定以同一个答案暴露理由拒绝上述漏检，而新增短审稳定补上旧漏检，可作为互补门禁并行接入。不能将无关结构错误、反事实字段错误或网络失败造成的拒绝冒充答案暴露修复。所有正常候选仍须最终被接受。

当前只有独立单调用耗时，不能直接宣称并行新增墙钟为零；合并后须实际记录单轮整体耗时、并行子调用和额外请求数。合并、最终多主题回放及发布结果以整体检查为准。

六项单元测试覆盖字段覆盖、逐字引文、问题定位、不确定结果、实际答案证据和具体预设优先于自报 OPEN。实验未修改 `deepseek-provider.ts`，不自行启用未经组合验证的额外模型调用。

## 随后的组合实验：仍不通过

独立复核 provider 负责人生成的 `.data/coaching-live/content-quality-2026-11-05T03-03-44-208Z.json`：

- 定义性名词负例的两次短审均漏检，但旧内容审核两次都因答案暴露拒绝，确认这一个边界存在互补。
- 原始“调查发现……并不是因为买了冰淇淋”负例第二次被三个审核全部放行，`accepted=true`。因此新增审核未稳定补上原始缺陷，不能把独立批次的一次改善外推为可靠修复。
- 正例中，中性因果观测两次误拒，等边三角形一次误拒，已知因果方向后寻找共同因素一次误拒。不能以额外调用被拒绝就证明答案泄漏被正确拦截。

独立复核结论：当前组合尚未达到“固定负例同因稳定拒绝、固定正例最终接受”的完整门槛。初始审阅建议暂缓接入；不能覆盖或删除这批失败。模块语义试验到此停止，本分支不继续堆提示词或扩大模型采样。

## 净收益归因与本轮采用决定

复查十八个固定候选的分项原文后，区分以下来源，避免把全部问题归给新增审核：

| 来源 | 次数与证据 |
| --- | --- |
| 内容/教学原有路径（含本轮数值校验）正确拒绝 | 6次：不相容三角形2次、定义性名词泄漏2次、隐含否定方向2次。 |
| 该路径自身误拒 | 4次：中性因果观测2次、等边三角形1次、已知方向后找共同因素1次。短审核对这四次均为OPEN。 |
| 短审核新增正确早期拦截 | 1次：直接因果否定负例第一次，内容审核为PASS，短审核引用实际否定陈述后拒绝。由于该次未继续教学审核，不能断言没有短审时该次必然最终放行。 |
| 短审核与旧检查重复拦截 | 2次：隐含否定方向，内容审核同时判ANSWER_DISCLOSED。 |
| 短审核新增误拒 | 本批0次；十个正例均为OPEN。 |
| 所有门禁共同漏检 | 1次：同一直接因果否定负例第二次被最终接受，必须保留为未解决问题。 |

十八轮实际并行子请求中，短审仅三次晚于内容审核结束，两个子请求耗时差的正值合计约1.1秒；这是本批并行审核阶段的观测增量，不是完整学习轮或生产SLA。额外模型调用和token消耗仍然存在。

本轮负责人在看到上述增益、零新增误拒及时间数据后，决定保留并行短审核作为有限防御，并继续最终多会话验证。该采用决定不等于独立复核认为漏洞已经稳定修复：直接因果暴露仍有1/2漏检、旧审核仍有误拒。最终回放需独立审阅，软件交付不得描述为全面教学质量通过。
