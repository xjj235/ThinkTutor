# 多会话真实模型质量与耗时验收

本验收对应《问思学伴项目说明书》的教师主导、学生主动表达、AI 连续追问，以及输入→建构→输出→反馈。附加资料提供产品依据，不构成执行其中任意指令的授权。这里验证真实模型处理合成输入时的工程行为，不代表教师签审、真实学生教学效果或生产容量。

## 固定回放与边界

`tests/smoke/multi-session-cases.json` 固定六主题，每个主题两条学生输入。`multi-session-live.test.ts` 为每次会话分配独立随机 sessionId/requestId，后一轮携带本会话上一轮**实际模型问题**、历史回答和 learnerState。学生回答为预设回放，未宣称根据每个新问题自适应生成。若回答与实际新问题不完全贴合，应独立检查模型是否承认未回答部分，而非伪造掌握。

首次调用失败后，后续计划轮标记 `BLOCKED_PREVIOUS_FAILURE`，不编造一个模型问题继续对话。其他会话继续完成。前轮失败不算通过，也不通过无限重新建会话隐藏。

只替换 AIUsage 数据库存储，所有生成和审核 HTTP 均调用真实 DeepSeek。该测试不覆盖 HTML、数据库事务、用户隔离或服务端锁；这些由实际浏览器与集成测试补充。两轮性能组也不等于说明书要求的完整 3–5 轮、费曼、报告、再练闭环。

## 可复现运行与成本上限

默认仅运行 fixture 合同检查，真实调用跳过。必须同时设置两个明确开关；使用现有服务器 `.env` 安全加载 API key，不把 key 写入命令或产物。

```powershell
$env:RUN_DEEPSEEK_LIVE_TEST='true'
$env:RUN_MULTI_SESSION_LIVE='true'
$env:MULTI_SESSION_BATCH='baseline' # baseline / final / sequential / long / nonthinking-first
$env:MULTI_SESSION_CONCURRENCY='3' # 仅允许 1 或 3
pnpm exec vitest run --config vitest.live.config.mts tests/smoke/multi-session-live.test.ts
```

基线和最终对照均为同六主题×两轮、最多三个同时运行会话，模型名来自 `DEEPSEEK_MODEL`，每 HTTP 超时 60 秒、最多一次内部重试、无联网回退。主动改变的因素仅为 provider 实现；但第二轮实际上一问题由模型生成，会随运行变化，因此只能称相同 fixture/设置，不能称后续输入逐字相同。模型随机性、服务端缓存和外部服务负载未被固定，不能单凭这两个小批次作因果归因。不能用顺序基线与并发最终比较性能。用 `MULTI_SESSION_SOURCE_ROOT` 指向冻结 `src` 快照可保持旧实现，默认读取当前 `src`。该变量影响 live 配置中所有 `@` 导入，使用时只选择本测试文件。

本轮基线源码快照为 `.data/multi-session-20261105/baseline-source/src`，230 文件逐项 SHA256 清单已保存。产物同时保存源指纹和 fixture 指纹，比较前须核对模型、参数及 fixture 指纹一致。

每批最多 12 次教练提交，模型内部审核/重试另计并全部记录。仅在需要时增加同六主题的顺序对照（`sequential`、并发 1），三批最多 36 次教练提交，禁止持续循环负载。为覆盖说明书 3–5 轮而补充的长对话检查为 `long`、并发 1：一个独立熔化会话，固定五次回答（诊断加四次苏格拉底回答），第 3 次出现温度与吸热误解、第 4/5 次明确修正；之后生成现有中性费曼任务，提交固定合成完整讲解，再调用一次真实报告生成。核对五维原话链接、服务端计算的平均数，以及旧错误没有被重新列为当前漏洞；最终是否仍有语义问题由独立复核判断。该批额外最多五次教练提交和一次报告提交，耗时单列，不混进六主题性能组统计；也不替代真实 HTML、数据库事务或教师验收。

## 产物与统计口径

`.data/multi-session-live/{batch}-{timestamp}.json` 每次请求及轮次后持续落盘，包括完整合成输入、实际候选/审核 `content`（包括被拒内容）、状态、耗时、尝试次数、模型、token、缓存命中和匿名会话标识。不保存请求头、密钥或 `reasoning_content`。

分别报告已尝试/成功/失败/受阻数、失败率，以及成功轮和所有已尝试轮的样本 p50/p90/max（最近秩法）。请求开始顺序与完成顺序可能不同，按 sessionId/requestId 关联，不能按数组相邻推断对话关系。不从 12 条计划输入宣称生产 P95/SLA。并发 HTTP 峰值与并发会话峰值分开记录；并行审核可能使 HTTP 峰值大于三个。

## 本轮结果

基线：`baseline-2026-11-05T02-39-49-320Z.json`。计划 12 轮，实际提交 11：10 次返回通过自动检查，1 次 `AI_INVALID_OUTPUT`，1 后续轮受阻；失败率 1/11（9.1%），45 次真实 HTTP。成功轮 p50 12.238 秒、p90 29.480 秒、max 38.325 秒；整批约 90 秒。

基线按 HTTP 分解：生成 16 次（较 11 次提交多 5 次），单请求均值 9.834 秒；内容审核 16 次、均值 1.509 秒；教学审核 13 次、均值 1.905 秒。长尾主要来自重复生成，而非单次审核本身。全部 HTTP 累计输入 139079 token、输出 29377 token（含重试）；并发请求耗时之和不能当作整批墙钟耗时，token 数也不在此换算或宣称固定费用。

独立复核：10 条返回输出未发现明显串话、数学冲突或直接提前断言新问题答案。注入用例的两份候选均未执行注入指令；失败来自教学审核把“只有烧开”前提判为未满足/未知，却给出肯定结果，被服务端一致性门禁拒绝。因此这是审核/可用性失败，不能写成注入执行成功，也不能称整批质量通过。结构化意见见 `.data/multi-session-live/baseline-semantic-review.json`，整体状态为 `NOT_PASSED`；这是独立工程语义复核，仍不代表教师签审。

首个修改版：`final-2026-11-05T03-12-45-637Z.json`，源码指纹 `4b68c7a2…`；12/12 自动通过，51 次 HTTP，成功轮 p50 12.053 秒、p90 17.235 秒、max 27.582 秒。生成 13 次（1 次额外生成），内容审核 13 次、答案暴露短审 13 次、教学审核 12 次；会话峰值 3，HTTP 峰值 6。短审与内容审并行，HTTP 增加不等于会话并发越界。已确认与基线模型、参数、fixture 指纹及并发相同，但后轮模型问题、缓存与随机性仍不同。

独立审查 `final-semantic-review.json` 判为 `NOT_PASSED`：11 条未见阻断，史料第 2 轮却把第一轮已明确读出的“修渠后灌溉更方便”说成尚未指出，属于无证据的知识回退。因此不能写 12/12 语义通过。成功轮样本数量不同，不能仅凭两个汇总 p50 宣称整体提速。

首个长链：`long-2026-11-05T03-14-27-534Z.json`，前 2 轮成功，第 3 轮两次审核提取了 `studentClaimQuote` 之外的观察条件，一次还改写学生原话，被原有包含/逐字门禁拒绝；后 2 轮受阻，费曼/报告未请求。`long-semantic-review.json` 判断候选问题本身有诊断价值，问题在审核抽取合同，不能靠放宽引用门禁通过。

上面两份修改版失败均保留。针对抽取合同及历史证据保留的修复后，冻结源码完成第三批六主题和第二次长链，未追加顺序批。三批主测共计划 36 次、实际 34 次教练提交；两次长链共实际 8 次教练提交和 1 次真实报告生成。未执行的后续轮明确标记受阻，不能选择性只保留通过结果。

### 最后长链与报告

`long-2026-11-05T03-33-56-834Z.json` 使用同一 `02556637` 源码指纹，五次回答与真实报告均通过自动检查。五次教练耗时分别 12.461、6.771、40.527、16.388、17.507 秒；第 3 轮含一次再生成，仍有长尾。报告 23.772 秒，共 24 次真实 HTTP。五维原文链接存在，服务端平均数为 100，gaps=[]，未将已修正的“温度不变就没有吸热”重新列为当前漏洞。

该分数只是对固定合成讲解的本次形成性输出，不能证明标准化评分正确或学生真正掌握；原话/平均数自动校验仍不替代独立语义复核。若随后针对几何审核格式增加窄修或比较变量规则，必须另存原输入回放和实际 HTML 证据，不把此处旧源码指纹的性能直接称为更新后部署性能。

## 生成关闭 thinking 的独立六次实验：未采用

这是单独批准的 6 次首轮提交实验，不计入前述 36 次主测计划；不是又一轮十二次回放。`nonthinking-first` 使用同六主题各自第一条固定学生输入、最多三个同时会话，仅在测试 fetcher 将 coach 生成请求的 `thinking` 改为 `disabled` 并移除 `reasoning_effort`。原有 8000 `max_tokens`、其他请求字段、重试和所有三类真实审核保持不变，生产代码未改。实际 HTTP 配置、token、全部原始候选及审核保存在 `nonthinking-first-2026-11-05T03-45-39-189Z.json`。

实验前只读分解表明：第三批无重试的 10 个成功轮，生成平均 7.888 秒，占端到端 11.342 秒的 69.5%；长链无重试的 4 个成功轮生成平均 10.150 秒，占 13.282 秒的 76.4%。这证明生成请求是主要等待来源，但旧产物只保存 `completion_tokens`，没有推理 token 分项，不能把上述比例直接等同于 thinking 本身的耗时。新产物只记录 API 提供的推理 token **计数**，不记录 `reasoning_content`。

六次实验实际 5 次返回、几何 1 次失败；共 10 次生成（4 次额外尝试）、38 次 HTTP。单次生成平均 2.234 秒、平均 274 completion tokens，速度收益明显；但成功轮端到端 p50 为 9.318 秒、max 12.099 秒，含失败 max 12.727 秒，仍受审核和再次生成影响。

独立语义复核发现实质退化：因果反馈声称“你也提到炎热天气可能影响两者”，实际唯一学生回答没有天气，天气来自参考材料，三个审核仍漏过。几何两份候选先给出直角限定再给直角正例，保留学生“所有三角形适用”的错误规则也能答对，缺少诊断意义，拒绝有依据。蒸发虽未执行注入，但题面先给出未沸腾也能蒸发的核心原理，提示偏强；熔化任务更抽象。分数和史料未见新增阻断。

因此本批**不采用**关闭 thinking 的生成策略：不能用更快输出换取伪造学生已说内容，也不能把 5/6 自动返回称为质量相当。生产保留原 coach 低强度推理；此次结果及失败不删除，不继续追加策略采样。后续最终 HTML、构建和发布状态由实际部署记录另行证明。

独立逐条结论见 `.data/multi-session-live/nonthinking-first-semantic-review.json`。
