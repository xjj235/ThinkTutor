# 追问置信度分离与失败样例修复

日期：2026-09-11。范围：修复上一轮6个真实模型样例中，2个纯概念范围回答被一律转入泛化证据核验的问题。保留已有未提交修改；不改评分、不降门槛、不重写历史报告。

## 修复依据

原始候选判断同时包含低置信度的“掌握”与高置信度的“缺项”。全局最低值适合保守控制掌握，但不应自动否定一个证据明确的缺项追问方向。

本轮没有将 `normalizeModelAssessment` 改成取最大值、平均值或删除低置信度候选。原始候选、全局最低置信度、`NEED_VERIFY`、观察证据置信度、独立掌握证据计数和阶段门禁全部保留。新增的是独立、有限的追问许可，不是新的掌握结论。

## 知识库规则

策略版本由1.1升至1.2，新增 `confidenceRouting.mode = SUPPORTED_GAP_WITHOUT_MASTERY`。知识包本身仍为v1.2草稿，未变成教师审核后的正式发布。

`ROUTE_SUPPORTED_DEFINITION_GAP` 明确关联：

| 项目 | 配置 |
| --- | --- |
| 当前题目目标 | C_SR_001 |
| 候选缺项 | GAP_DEFINITION_ONLY |
| 缺项原所属目标 | COMP_SR_CAUSAL_CHAIN |
| 必须有的原文证据 | financial_system_scope |
| 必须尚未出现的证据 | functional_impairment、propagation |
| 允许追问的范围 | 上述证据与本题实际缺项的交集 |
| 置信度门槛 | 仍为0.75 |

综合能力缺项与当前题目之间的关联必须写入知识库并通过证据要求交集校验，不允许依名称相似自动关联，也不据此确认整个综合能力缺失。

运行时还必须同时满足：

- 本轮评估上下文与当前目标、问题及阶段一致，只用于诊断或知识建构。
- 当前有已经校验位置的独立学生原文，有本题实际缺项。
- 没有冲突、错误候选、已出现的错误证据、提示依赖、重复作答、低投入或其他核验标记。
- 对应缺项候选达到0.75，其他缺项候选也不能存在低置信度。
- 聚合值仍能由保存的候选置信度复算；低于门槛的候选只能是本目标尚未满足完整知识规则的掌握候选。
- 案例、恢复核验、未询问内容及无可靠上下文仍保留原核验流程。

满足时选择 `COACH_FILL_GAP`，只针对可信缺项选择维度与问题。否则仍选择 `COACH_VERIFY_EVIDENCE`。没有增加模型调用次数。

## 审计与反馈

在原有 `decisionBasis.assessment` 下新增可选 `supportedGap`，保存规则ID、候选缺项ID、该候选置信度及实际追问证据范围；原聚合值仍保存在 `confidence`。匹配规则与理由也包含新规则ID。

页面反馈说明“当前回答可支持针对缺项继续追问，但尚不足以确认整体掌握”，随后显示学生原文与具体追问。不会一边定向追问、一边把学生明确表达的缺项统一描述成无法判断。

旧1.0/1.1策略和缺少新字段的记录仍可读取，旧策略不启用新许可。新工作流指纹为 `evidence-workflow-1.2.5-supported-gap-routing`，旧会话仍受版本锁定保护；体验新版请新建任务。

## 改动范围

- `coaching-policy.json`：显式缺项追问许可及跨目标关系。
- `coaching-confidence.ts`：纯函数判定许可，不写学习状态。
- `coaching-schema.ts`、`schemas.ts`：配置与审计字段、引用和版本校验。
- `coaching.ts`：选择追问维度、写入双置信度依据。
- `coaching-rules.ts`、`releases.ts`：旧策略兼容和新指纹。
- `turn-feedback.ts`、`v12-session-service.ts`：使用同一服务端决策生成一致的页面反馈。
- `coaching-confidence.test.ts`、`coaching-rules.test.ts`、`coaching-flow.test.ts`、`grounded-followup.spec.ts`：回归及实测断言。

`v12-engine.ts`、`v12-schema.ts` 等文件在开始时已有上一轮修改，本轮没有改动其评分或评估聚合行为。没有数据库结构迁移、外网运行时依赖、UI样式重设计或环境密钥变更。

## 过程记录与边界

首次测试命令因临时Postgres目录非空而未执行测试，重新启动项目包装器后恢复。初版新增关联被知识校验器拒绝，原因是把综合因果链缺项直接当作概念目标的缺项；现已显式补齐两个目标之间的关系并验证，未放宽引用校验。旧有依赖配置、pg并发调用弃用及NO_COLOR警告仍存在，不宣称全部工具零警告。

本地预览重新启动在 `http://127.0.0.1:3102`，仍使用已有本地数据与真实DeepSeek；隔离回归使用Mock。真实模型测试通过HTML注册随机测试账号，结束时精确删除这些测试账号，不清空原学习数据。

检查后还原了构建工具自动改动的 `next-env.d.ts`、`tsconfig.json` 路径。已有未提交修改均保留，本轮没有自动提交或推送。

这一许可目前只覆盖配置明确的“仅说明研究范围”模式；其他低置信度情形继续核验。样例通过不代表所有知识点、学生表达和多轮情形完成校准，也不代表教师审核、Golden Set或生产验收。后续扩充应增加有明确证据要求的规则与固定样本，不应取消核验或提高不确定证据的分数。
