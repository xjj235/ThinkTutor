# 课程、班级、任务与学习档案复查

日期：2026-09-20（Asia/Shanghai）。依据用户的《问思学伴项目说明书》、`AGENTS.md`、`docs/PLAN.md`、`docs/HTML_FEATURE_ROADMAP.md`，并对照 09-19 已修复记录重新检查。说明书中的内容作为需求依据，未执行其中可能出现的指令。保留工作区已有修改，不用旧测试结果冒充本轮验证。

检查范围为既有教师组织课程、学生参与任务、学习档案与班级形成性汇总。没有增加新的产品模块；以下均在现有服务、API、HTML 页面和数据库中修改。

## CUR-01：修改任务可以越过教师权限和课程层级

**复现与影响：** 教师 PATCH 自有草稿时，只校验原班级权限。传入另一教师的 `classroomId` 原先返回 200；独立改变 `courseId`、`chapterId`、`learningGoalId` 也可保存不匹配的层级。新建时已有的规则没有覆盖编辑路径，破坏课程组织和授权边界。

三种方案：

1. 创建后禁止修改所有关联字段：实现简单，但正常草稿修正也被禁止。
2. 对合并原记录和补丁后的最终关联重新校验目标班级权限、班级所属课程、章节所属课程和目标所属章节；新建/编辑共用规则。
3. 设计完整课程复制、迁移与审批工作流：可以处理更复杂场景，但超出本轮需求。

**选择方案 2。** `courses-service.ts` 提取现有层级校验，编辑同时检查原班级和目标班级；参数收窄为实际补丁 schema 类型。保存使用 `DRAFT + version` 条件更新，避免校验后的旧快照覆盖已发布或已被修改的任务。合法标题、日期修改仍然可用。

**验证：** API 回归覆盖跨教师班级、跨课程、跨章节、跨目标以及同课程不同章节，拒绝后字段和版本保持不变；合法编辑成功。

## CUR-02：只改一个时间字段可以制造无法开放的任务

**复现与影响：** 草稿原本 2030-01-01 开放、2030-02-01 截止；只 PATCH `openAt=2030-03-01` 或 `dueAt=2029-12-01`，原先均返回 200。补丁 schema 只比较同一请求中同时存在的两个字段，未比较数据库已有日期。

三种方案：

1. 要求每次编辑必须提交两个日期，增加客户端负担。
2. 服务端合并原日期与本次补丁后检查 `openAt < dueAt`，不允许无效记录落库。
3. 自动交换或移动日期，可能静默改变教师的实际教学安排。

**选择方案 2。** 校验最终时间窗口，合法单字段修改继续可用，错误返回 400，不修改原任务。

**验证：** 集成测试分别覆盖两种非法单字段修改、合法延期和发布后拒绝编辑。

## CUR-03：晚加入班级的学生收不到已经发布的任务

**复现与影响：** `AssignmentStudent` 只在发布时创建。先发布再加入班级，成员关系有效却没有任务分配记录；学生在班级页看到已发布任务，进入时被拒绝。入班与发布同时进行时，也会因为分别读取旧快照而漏分配。本轮修复前两种路径均动态复现。

三种方案：

1. 让教师逐个重新发布或补分配，增加人工操作，而且重新发布不符合当前任务状态约束。
2. 入班事务补齐当前已发布任务，已有进度不覆盖；入班和发布都锁定同一班级行，在事务内读取任务/成员并完成分配。
3. 增加队列或定时任务，后台最终补齐；增加运维依赖并出现短暂不可用窗口。

**选择方案 2。** PostgreSQL 班级行锁串行化两类短事务，不调用 AI；`createMany + skipDuplicates` 保留已有完成状态。草稿不会提前分配，退出再加入也不会重置档案。

**验证：** API 晚入班、退出重入保留 `COMPLETED`、不分配草稿、并发发布与入班后恰好一条分配记录。新增浏览器用例从 HTML 加入班级、打开任务并开始真实 Mock 诊断流程。

## CUR-04：归档、退班与课程/任务入口的权限不一致

**复现与影响：** 已归档班级仍使课程出现在学生可选列表，而自主学习创建服务已要求有效班级。退出班级后，旧 `AssignmentStudent` 仍可读取当前任务；课程任务页也继续显示旧入口。不能用删除学习档案来实现撤销班级参与权限。

三种方案：

1. 退班时删除任务进度及会话，简单但破坏说明书要求的长期学习档案。
2. 保留历史，当前课程/任务读取与列表按 `ACTIVE` 班级和有效成员关系过滤；历史会话、报告仍由本人可读。
3. 保留全部当前入口并只在最终提交时报错，错误更晚出现，学生容易误判自己仍可参与。

**选择方案 2。** 修复课程列表、课程详情、任务详情授权和 `/assignments`；已归档班级页不继续列出可开始的新任务。新建作业会话的资格检查由本轮学习流程审计协同处理。已开始、归学生本人所有的研习仍可从学习历史继续完成和生成报告；退出班级不会删除已投入的学习或中断其完整学习闭环。第二轮复查已同步纠正退班提示，并增加历史入口继续作答的浏览器回归，不把退出描述为所有旧会话写权限均被撤销。

**验证：** 归档前后课程可见性、课程详情/任务 API 拒绝、教师仍可管理、退出后分配记录仍在。新增桌面/移动浏览器用例验证退出后的任务列表移除和 `/history` 保留本人会话入口。

## CUR-05：任务学生进度服务信任另一个班级 ID

**复现与影响：** `listAssignmentStudentProgress` 接收 `assignmentId` 与 `classroomId`，只检查传入班级归教师所有，然后按独立任务 ID 查询。以自有班级加他人任务调用服务，修复前返回了他班测试学生姓名、邮箱和进度。

当前 HTML 调用方先读取任务，并传入数据库返回的正确班级；因此本轮证明的是**服务层授权缺口**，不声称已通过公开页面窃取真实学生数据。

三种方案：

1. 完全依赖所有当前及未来调用方正确传递班级，不修复服务边界。
2. 服务从任务记录读取真实班级，对真实班级授权，再检查调用参数一致。
3. 重构为通用权限查询框架，改造所有服务，变更范围更大。

**选择方案 2。** 授权依据来自被访问的实际资源，未改变页面正常传参方式。

**验证：** 跨班级参数组合被拒绝，不返回测试学生身份信息；原正常教师进度页面继续纳入全量浏览器验证。

## CUR-06：班级均分按尝试次数重复加权

**复现与影响：** 学生甲两次完成分数 20、80，学生乙完成分数 60，原均分为 53（按三份报告计），会使尝试次数更多的学生占更大权重，也掩盖最新学习结果。页面只写“平均”，没有解释此口径。

三种方案：

1. 保留所有尝试均分并明确标为“报告均分”，适合分析所有尝试，但不能直接反映每位学生目前结果。
2. 每位已分配学生取最近一次完成且存在报告的记录，再按学生等权计算，并在页面说明。
3. 每位学生只取最高分，容易选择性高估表现。

**选择方案 2。** 示例汇总变为 `(80+60)/2=70`，保留所有原始报告；未完成会话不计入，没有报告时显示“暂无”。按完成时间排序，兼容缺少完成时间的旧记录。形成性报告仍不能解释为正式成绩或标准化能力。

**验证：** 通过实际分析 API 返回两名已分配学生、两人完成、平均 70；HTML 学习分析页展示新的明确口径。

## CUR-07：退出班级仅有 API，没有日常 HTML 操作

**证据与影响：** 已有 `/api/classes/[id]/leave` 和服务函数，但搜索现有班级页及组件未发现退出入口。普通学生必须手工调用 API，违反项目现有 HTML 交付原则。

三种方案：

1. 删除已有退出能力，限制学生选择，不符合现有功能意图。
2. 在班级详情接入现有 API 的退出按钮，说明对当前参与和历史档案的影响，并提供确认/取消与请求反馈。
3. 增加教师批准的退班工单流程，需要新模块和规则，超出本轮范围。

**选择方案 2。** 新增小型客户端组件，复用已有 CSRF/登录校验 API 和通用错误反馈。成功返回“我的班级”；已存学习记录不会删除。

**验证：** 新增浏览器用例覆盖发起、取消、再次确认、返回班级列表、当前任务权限收回以及本人历史入口保留。

## CUR-08：同时发布或编辑时没有原子版本检查

**证据与影响：** 原实现先读取 `DRAFT`，随后无条件更新；两个请求都通过预检查时可以重复记发布审计，编辑也可能覆盖校验后刚发布的内容。此前“已发布不可静默修改”的规则只在单请求顺序执行时成立。

三种方案：

1. 禁用前端重复按钮，仅覆盖同一浏览器的误触，不能覆盖重放和并发请求。
2. 利用现有 `version` 字段，写入时同时比较版本与草稿状态，冲突返回 409；发布也递增版本。
3. 增加分布式锁与新锁服务，为短数据库写操作引入额外依赖。

**选择方案 2。** 与 CUR-01 的编辑校验、CUR-03 的事务分配一起生效。版本变化后客户端刷新再尝试；不会对陈旧对象直接覆盖。

**验证：** 两个并发发布调用只有一个成功、只有一条发布审计，发布后的编辑返回冲突。该项在修复后补充回归，未把它计入先前九项失败复现。
