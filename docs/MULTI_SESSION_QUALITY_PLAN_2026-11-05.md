# 多会话真实模型质量与响应优化

依据：原项目说明书4.2–4.4、5.1–5.3及现有PLAN。目标是在多个独立会话、并行请求、错误与修正、不知道及不可信输入下，保持学生主动表达和可追溯反馈；不以单个成功请求代表稳定性能。

## 方案比较

| 方案 | 收益 | 代价与选择 |
| --- | --- | --- |
| 继续增加提示规则或重试预算 | 改动少，可缓解个别已知错误 | 容易重复生成和增加尾部等待；不作为主要方案 |
| 用固定正反案例校准审核，明确待答判断与提前披露内容，配合多会话回放及服务端隔离检查 | 能定位实际缺陷，保留现有学习闭环和权限规则 | 本轮优先验证；只发布有真实对照与误拒检查支持的修改 |
| 增加独立核验、有限领域校验或异步作业系统 | 可针对单一审核遗漏的内容提供补充证据 | 本轮有界验证短答案暴露审核与有限三角形数值校验；不引入通用求解器、其他模型提供方或异步作业系统 |

## 验证层次

1. 受控集成测试：同用户多会话、不同用户、重复请求、某个模型调用失败、限流及恢复；证明状态和授权行为，不能代替真实模型质量。
2. 真实模型：六个独立场景各两轮，基线与修改后使用同模型、重试、超时和最大三会话并发；保留每条原文、每次HTTP、失败及耗时。样本p50/p90/max仅描述本次回放。
3. 语义复核：是否一个主要问题、是否可回答、是否提前给答案、是否实际降低难度、是否基于本会话的学生原话、修正是否得到承认。
4. HTML：同一账号在三个标签页创建不同学习任务并实际作答，检查等待、响应归属与刷新后记录；隔离本地数据库，真实模型，不在公共站点做压力测试。

每一轮生成仍需通过服务端审核；失败不能推进阶段或伪造学生记录。有限测试无法证明开放领域模型永远正确，结构通过和语义通过必须分别报告。未通过的候选与未解决边界保留，不改断言使结果变绿。

## 基线定位与实施取舍

六会话基线实际11次提交、10次返回、1次审核失败、后续一轮受阻。共16次生成、16次内容审核、13次教学审核；单次HTTP平均约9.834、1.509、1.905秒。主要长尾来自重复生成，不能简单通过省略审核解决。

直接提高内容审核推理强度曾出现36–41秒后无有效输出；短结构替换也未稳定抓住所有坏例，这些实验不直接作为上线方案。优先修复服务端把“判断规则主张本身”和“推断具体实例结果”混同所导致的误拒；另验证与原审核并行的短答案暴露检查，以及对已提取、带来源的完整三角形约束执行有限本地计算。新增检查的成本、误拒和未覆盖边界也要计入最终结果。

最终结果见 `MULTI_SESSION_REAL_ACCEPTANCE_2026-11-05.md`、`MULTI_SESSION_ISOLATION_2026-11-05.md` 与本轮原始记录。第7项仍不在处理范围；原Render站点只更新经过整体验证的改动。
