# 浏览器学习流程复查

日期：2026-09-20。依据项目说明书的电脑/移动网页、学生主动表达、反馈后再次学习要求，以及现有 HTML 路线图。保留已有修改；本轮新增修复如下。测试使用隔离 PostgreSQL 和 Mock，不代表实际手机独立网络验收。

## B1. 局域网 HTTP 浏览器缺少 randomUUID 时无法创建学习任务

自主创建直接调用 `crypto.randomUUID()`，作业入口更在组件初始化时调用；浏览器没有该方法时，前者显示误导性网络错误，后者无法正常呈现入口。项目已有可信局域网预览，因此这个入口必须兼容。

| 方案 | 取舍 |
| --- | --- |
| 1. 要求所有本地和局域网预览都配置 HTTPS | 能提供安全上下文；增加本地证书管理和手机信任设置要求。 |
| 2. 缺少 UUID 时用毫秒时间作为请求 ID | 简单；同毫秒、跨标签页可能冲突，不适合幂等请求。 |
| 3. 用浏览器 getRandomValues 生成 128 位随机 ID，点击操作时才生成 | 支持现有预览，随机性足够，不必新增依赖。 |

选择 **3**。`client-request-id.ts` 供任务、会话、报告和作业入口共用；同次失败重试仍复用同一 ID，不因重试生成新学习记录。浏览器回归显式移除 `randomUUID`，验证自主创建、作答及教师作业开始；这是能力缺失模拟，不冒称真机网络测试。

## B2. 创建成功至跳转完成之间，作业与再练按钮重新开放

原作业和报告入口在 `router.push` 后立即于 `finally` 解锁，同时清空/更换请求 ID。页面加载慢时，学生可以再次点击；原报告存在多个 OPEN 要点时可能意外开始下一个要点的巩固。React 状态也不能作为同一事件轮次内的同步防重锁。

| 方案 | 取舍 |
| --- | --- |
| 1. 成功后按固定延时禁用按钮 | 改动小，但网络快慢不确定，仍存在重复窗口。 |
| 2. 只依赖服务端幂等和活跃会话检测 | 服务端保护必要；前端更换请求 ID、另一要点可开启时仍可能产生新操作。 |
| 3. 同步 ref 防重复，导航成功前保持 pending，同次失败复用 ID | 覆盖双击和慢导航，继续复用已有服务端幂等机制。 |

选择 **3**。作业与定向巩固入口只在失败时解锁；成功后保留锁直至导航离开。浏览器用暂停目标页面响应模拟慢导航，确认按钮禁用且数据库仅有一个子会话。

## B3. 教师查看学生报告/会话时出现本人专用操作

教师获准阅读其作业下的报告，但原报告显示“开启定向巩固”，会话页也显示学生作答入口；点击后服务端正确返回403。界面表达的能力与服务端实际授权不一致。

| 方案 | 取舍 |
| --- | --- |
| 1. 保留按钮，点击后说明只有学生能操作 | 不影响权限安全，但让教师走入必然失败的流程。 |
| 2. 新增单独教师报告/会话页面 | 可完全分离操作；重复视图与评分展示容易漂移。 |
| 3. 复用原页面，服务端依据查看者与会话所有者传入只读状态 | 保持同一 HTML/数据实现，权限清楚，开发量小。 |

选择 **3**。页面先校验登录与会话访问权限，再显示只读提示，隐藏他人的作答、目标确认、恢复核验和创建巩固入口。所有写入 API 继续校验本人权限；隐藏按钮不被当作安全机制。教师发布到报告浏览的 E2E 增加只读检查，并直接调用写入 API 确认403。

## 第二轮发现的旧草稿刷新路径

该问题归入[核心 C1](PROJECT_AUDIT_2026-09-20_CORE.md)：已有会话收到终止性输入错误后，点击“刷新会话”原本更新进度/版本却保留当前输入框草稿，旧答案会获得新版本。现在既有会话刷新统一走进度同步：未保存的草稿另行展示供复制，当前作答框清空。初次加载失败仍使用原加载逻辑。

双标签页浏览器回归分别覆盖直接409冲突，以及400错误后另一个标签页推进、再刷新会话的场景；两者均不得写入旧草稿。
