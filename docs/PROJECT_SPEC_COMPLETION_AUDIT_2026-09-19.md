## 二、影响完整学习流程的三个问题

### 1. 系统性风险 v1.2 达到轮数上限时，可能跳过独立费曼讲解

触发条件：v1.2 会话处于苏格拉底阶段，完成本次回答后达到 `maxTurns`，且未走入案例迁移通过的费曼分支。

当前行为：[状态机](D:/Codex/New%20project/src/lib/state-machine.ts:157)把顶层阶段设置为 `FEYNMAN`，但教学子阶段直接设置为 `REFLECTION`。随后[会话服务](D:/Codex/New%20project/src/lib/knowledge/v12-session-service.ts:116)显示反思问题；反思提交后，状态机可以转入报告。这条路径没有经过独立 `FEYNMAN_OUTPUT` 表达。

影响：页面或顶层状态叫“费曼”不能替代实际完成费曼讲解；该分支未完整兑现说明书“经过连续思考后，用自己的话重新解释知识”的独立输出环节。

本轮动态复现：纯状态转换检查确认第5轮直接进入 `REFLECTION`，随后提交可进入 `REPORTING`。脱敏记录见 [boundary-check.json](../.data/spec-audit-20260919/boundary-check.json)。

建议验收条件：达到轮数上限可以保留未掌握状态，但仍应要求一次独立费曼表达，再进入反思和报告；增加覆盖该分支的状态机及浏览器验证。本次仅报告问题，未修改行为。

### 2. 再练结束后，没有重新判定或结束原薄弱点的巩固状态

当前行为：[开始再练](D:/Codex/New%20project/src/lib/session-service.ts:646)把原 `LearningGap` 从 `OPEN` 改为 `IN_PROGRESS`，并通过 [sourceGapId](D:/Codex/New%20project/src/lib/session-service.ts:652)关联子会话。但当前检查到的[通用报告完成事务](D:/Codex/New%20project/src/lib/session-service.ts:553)和 [v1.2 报告完成事务](D:/Codex/New%20project/src/lib/knowledge/v12-session-service.ts:175)没有依据该关联和再练证据回写原薄弱点。

影响：子会话能够完成并生成新报告，原报告仍可能长期显示“巩固已开始”。[报告页面](D:/Codex/New%20project/src/components/report-client.tsx:170)依据原薄弱点状态展示入口与提示，学生难以从原报告确认该问题是否已解决。

本轮动态复现：在隔离数据库和 Mock AI 中运行真实业务服务，原会话与再练均达到 `COMPLETED`，两份报告均已保存，原薄弱点仍经历 `OPEN → IN_PROGRESS → IN_PROGRESS`，`resolvedAt=null`。该审计测试1项通过，见 [gap-retry-evidence.json](../.data/spec-audit-20260919/gap-retry-evidence.json)和[执行日志](../.data/spec-audit-20260919/gap-retry-run.txt)。它证明状态没有重新判定，并不证明这次学生作答理应被认定为掌握。

建议验收条件：依据再练后的真实证据明确更新原薄弱点为已解决或仍需巩固，保留来源关系与审核依据；不能只因完成一次再练就自动声称掌握。本次未修改数据或状态。

### 3. 教师学习目标允许 2000 字符，学生会话只允许 400 字符

触发条件：教师创建超过 400、且不超过 2000 字符的合法学习目标，学生选择该目标开始学习。

当前行为：[教师目标 schema](D:/Codex/New%20project/src/lib/domain-schemas.ts:30)接受最多 2000 字符；[学生会话长度合同](D:/Codex/New%20project/src/lib/contracts.ts:80)只接受 400 字符。[任务解析](D:/Codex/New%20project/src/lib/session-service.ts:211)取回教师目标后重新按会话 schema 校验，造成合法教师目标无法进入学生学习流程。学生表单也会[直接使用该目标正文](D:/Codex/New%20project/src/components/task-form.tsx:243)。

影响：“教师设定目标 → 学生选择目标 → 创建任务”的纵向流程在这一范围内不完整。

本轮动态复现：同一段500字符目标通过教师目标 schema，却被学习任务 schema 拒绝，见 [boundary-check.json](../.data/spec-audit-20260919/boundary-check.json)。

建议验收条件：统一保存、页面和会话合同，并用实际长目标覆盖教师创建到学生开始学习的完整流程；不应静默截断教师目标。本次未修复。

以上三项已分别通过代码检查和本轮动态检查确认；本轮原有通用测试通过不表示这些问题已被修复。

## 三、教学资源与比赛成果的实际边界

现有系统性风险资源包含八个案例，见[案例资源起点](D:/Codex/New%20project/knowledge/courses/financial-risk-management/systemic-risk/manifest.json:1692)。v1.2 将它们明确标为[教学构造案例](D:/Codex/New%20project/src/lib/knowledge/v12-resources.ts:98)，不应描述为已经核实的真实历史事件。

另有五类金融风险参考主题和 40 个知识单元，见[参考资料目录](D:/Codex/New%20project/src/lib/knowledge/reference-library.ts:53)及[学生目标选择](D:/Codex/New%20project/src/lib/knowledge/student-catalog.ts:9)。它们确实能供学生选题；但[资料接入边界](D:/Codex/New%20project/src/lib/knowledge/reference-library.ts:66)只把学科正文用于学习上下文。02–08 文档中的流程、案例、评分规则及 Prompt 仍是教师参考，不能把“文档已导入”称为“每个主题的完整教案规则都已执行”。既有[导入核查](FINANCIAL_RISK_REFERENCE_IMPORT_2026-09-16.md)还记录了案例映射需要教师复核的问题。

随库 v1.2 的[发布状态](D:/Codex/New%20project/src/lib/knowledge/v12-resources.ts:62)仍为 `draft`，审核人和时间为空；[Golden 文件](D:/Codex/New%20project/knowledge/golden/systemic-risk/routing.json:2)明确标记待教师审核，并说明其只是候选信号驱动的工程路由回归，不是真实模型评测基准。历史[实现报告](SYSTEMIC_RISK_V1_2_1_IMPLEMENTATION_2026-09-06.md)也列明教师来源核验、Golden 和签署尚需补充。

数据库可以另行存储[已发布知识版本](D:/Codex/New%20project/src/lib/knowledge/releases.ts:32)。本轮未读取线上审核数据库，因此准确结论是“检查到的随库资源及交付记录尚不足以证明正式教学审核完成”，而不是断言线上绝无其他审核记录。

比赛环境显式[允许草稿知识](D:/Codex/New%20project/render.yaml:29)。[部署说明](FREE_COMPETITION_DEPLOYMENT_2026-09-18.md)将其定位为待审核示例和少量比赛体验，并记录教师新增材料上传在此环境禁用；阿里云正式生产的审核、存储及运维要求仍另行成立。

本次未发现真实课堂试用、教师评价或学习前后效果成品证据。2026-09-18 的公网学习记录使用合成作答，部署文档明确说明它只是功能验证。不得据此宣称学生能力或教学效果已经获得证实；这属于效果证据未验收，不是要求新增一个产品模块。

文件检查范围是仓库内与交付相关的非测试产物、`D:\桌面\数据实现` 目录中的文件名，以及其知识库子目录。该范围内：说明书 MD/PDF 已有，演示视频和比赛答辩成品未发现。仓库原有[需求追踪](PRODUCT_REQUIREMENTS_TRACEABILITY.md)也把视频和答辩材料列为未实现。若成品保存在其他位置，提供现有文件即可进一步核验，无须认定它们一定不存在。

## 五、完成判定与剩余事项

按说明书原始范围，当前可以说“网页平台、AI 教练和学习档案的主功能基本完成，已有可在线访问的比赛体验环境”；不宜说“说明书全部内容已经做完”。

剩余事项按作用区分：

1. **软件完整性：** 修正上限分支跳过独立费曼、再练不回写原薄弱点、教师与学生目标长度不一致三个问题，并补针对性验证。
2. **已列明的成果：** 补齐或定位现有项目演示视频、比赛答辩成品，按实际赛事格式检查；本次未擅自新增赛事要求。
3. **教学可用性证据：** 对准备正式教学使用的案例、来源与评价规则完成教师审核和必要模型校准，保留真实签署和版本记录。
4. **尚未核验的实际条件：** 按拟交付环境补独立手机网络、真实使用反馈和所需生产验收。阿里云正式生产不应与已上线的 Render 比赛体验混为一谈。

旧文档中的“真实上线未验证”结论存在时间差：[原需求追踪](PRODUCT_REQUIREMENTS_TRACEABILITY.md)尚未反映09-18的比赛站部署，应结合[较新部署记录](FREE_COMPETITION_DEPLOYMENT_2026-09-18.md)和本轮公网复查理解；同样，旧文档中声称已完成的流程也不能覆盖本轮发现的边界缺陷。
