# 真实模型复核、性能修复与未解决边界

记录日期：2026-11-04 至 2026-11-05（北京时间）。模型：`deepseek-v4-flash`。所有学生内容为合成测试数据，不是学生教学成效研究，不是教师认证。`PENDING_TEACHER_REVIEW` 保持不变。

## 1. 本轮已定位的慢失败

蒸发主题的实际浏览器第二次作答耗时 **44.979 秒后返回 502**。三次生成都额外依赖“标准气压下水的沸点为100°C”，但本任务引用材料只有“达到相应气压下沸点”。内容审核虽自报 PASS，服务器仍因 `prerequisiteEvidence.source=UNSUPPORTED` 拒绝。这里是任务证据范围不足，不是把 100°C 常识认作事实错误。

三种方案比较：

| 方案 | 判断 |
| --- | --- |
| 增大超时或重试次数 | 会重复无来源依赖，增加等待，未采用 |
| 首轮优先使用资料已有定性条件；重试明确指出未获支持的依赖 | 已采用；纠偏数据仍是不可信数据，每条最多240字、最多4条，不传私有答案或推理 |
| 合并或取消语义审核 | 可能节省一个审核调用，但削弱当前门禁，未采用 |

同输入 provider 修复前在一次重试上限下：生成15.641秒、内容审核1.986秒、重新生成10.659秒、再审核1.739秒，约30.3秒后失败。修复后一次观测为生成9.118秒、内容审核1.638秒、教学审核2.469秒，合计13.238秒成功。原失败浏览器会话用原答案重试为 **12.805秒、HTTP 200**；失败前阶段仍为 SOCRATIC、轮数0，拒绝的答案未入库。

- `.data/coaching-live/calibration-2026-11-04T15-59-21-443Z.json`

## 2. 明确未通过的语义样例

### 2.1 相关与因果：题干提前给出判断方向

最后跨学科批次自动合同检查5/5通过，但独立语义复核认定 `data-correlation-causation` 第一轮 **答案暴露，语义验收失败**。模型内容审核返回PASS，最终输出也被接受；不能用自动通过掩盖这项失败。

最小复现输入：

```json
{
  "task": {
    "topic": "相关与因果",
    "objective": "区分共同变化和因果解释",
    "learnerLevel": "入门",
    "referenceText": "两个量一起变化只能说明相关，不能单凭这一点确定因果。第三个因素可能同时影响两者。例如炎热天气可能同时增加冰淇淋销量和游泳人数。观察记录不是随机分配的实验。"
  },
  "latestAnswer": "冰淇淋销量和游泳人数一起增加，所以一定是买冰淇淋使人去游泳。",
  "phase": "SOCRATIC",
  "socraticTurns": 0,
  "maxTurns": 5,
  "unknownStreak": 0,
  "learnerState": null
}
```

`messages` 仅含上述 latestAnswer 的 USER/SOCRATIC 消息。实际候选：

> 某地连续高温，冰淇淋销量和游泳人数都上升；调查发现人们去游泳是因为天气炎热，并不是因为买了冰淇淋。仅凭“两者一起上升”这一观察，能否证明买冰淇淋使人去游泳，依据是什么？

候选 `questionType=COUNTEREXAMPLE`，focus 为“先用这个具体情形判断：同步上升本身是否足以支持该因果结论”。题干已断言“并不是因为买了冰淇淋”，后半句再询问同一因果命题。继续要求依据不能恢复独立判断证据。

同场景第三轮仍沿用新的手机/近视情境是合理的，因为预设回答错误沿用了天气解释；但问题未缩到focus承诺的“指出第三因素”，仍完整重问因果判断与依据，属于支架不足。

完整出处：`.data/coaching-live/calibration-2026-11-04T16-10-19-352Z.json` 的 `turns` 与 `drafts`；可复现输入由 `tests/smoke/coaching-calibration-cases.json` 保存。

### 2.2 三角形数值自洽：内容审核漏判，最终因其他原因被挡下

固定候选：

> 一个三角形的三个角分别为50°、60°、70°，已知其中两条边长分别为3和4，能否直接用勾股定理求第三边，依据是什么？

输入学生主张为“任何三角形只要知道两条边，就能用勾股定理求第三条边。”参考材料为“勾股定理适用于直角三角形，两条直角边的平方和等于斜边的平方；斜边是直角所对的边。”

全角50°/60°/70°下任意两边的最大比值为 `sin(70°)/sin(50°)≈1.22668`，小于`4/3≈1.33333`，故这些给定不能同时成立。真实内容审核仍返回PASS。最终管线 `accepted=false`，由教学审核 `meaningfulExplanation=false` 拒绝，**并非数值冲突门禁正确识别**。不能由这次拒绝推断数值门禁可靠。

最后原有生成回归为4通过、1失败；失败的固定候选测试保留原断言，不为取得绿色结果降级或删掉。出处：`tests/smoke/coaching-live.test.ts` 的 `real reviewer rejects incompatible complete triangle angles and side lengths`；`.data/coaching-live/recheck-2026-11-04T16-07-35-894Z.json`；`.data/optimization-20261104/real-generation-final.log`。

### 后续可选方案（截至11月4日未实施）

1. 将复核结构明确拆成“本轮仍待判断的命题”“题面/反馈是否已给同一方向”“对应原文”，以固定正反样例校准。对答案暴露问题优先考虑此方案，但需要验证误拒与延迟。
2. 对可结构化的数值题设增加独立领域验证器。必须验证提取出的对象、对应关系、近似误差及单位；不采用自由文本三角函数正则来猜题意。数值自洽问题优先研究此方案，当前未实现。
3. 对这些已保存的候选比较更强的审核模型或有界推理配置，再根据准确率、误拒和耗时取舍。没有证据表明简单换模型即可解决全部问题。

11月5日后续：已实现带原文证据的有限三角形数值校验，并验证两个矛盾候选被本地数值检查拒绝；这不覆盖未被模型提取出的条件。新增与原内容审核并行的短答案暴露复核有额外早期拦截，但同一因果候选仍出现一次全部门禁放行，不能宣布语义漏洞彻底消除。新的多会话、隔离、真实HTML结果及剩余限制统一记录在 [多会话验收](MULTI_SESSION_REAL_ACCEPTANCE_2026-11-05.md)，本节历史失败不被后续结果覆盖。

## 3. 费曼任务与报告的后续窄修

原浏览器费曼任务称“你之前已经能用温度、表面积和空气流动来解释蒸发了”，此前USER仅实际解释温度影响；原始输入仅有task和生成的learnerState，缺少学生逐轮原文。这是无据历史掌握归因。中途尝试短专用提示后真实输出1.413秒、开头已中性，但requirements仍复述了蒸发定义等待解释结论，故没有把该尝试作为最终修复。

最终比较：继续叠加模型提示仍有采样失效；另加任务审核调用增加等待且仍依赖模型判断；服务端固定中性环节指令可直接消除无必要的评价与答案生成。本轮采用第三种，`src/lib/ai/feynman-instruction.ts` 由DeepSeek和Mock共用，仅引用主题，要求学生自己解释概念、依据、自选例子和边界，不拼接参考材料、confirmedPoints或gaps中的答案，也不发模型请求。这是进入讲解环节的指令，不是模拟学生评价；正常苏格拉底追问和报告仍调用真实模型。现有费曼接口及两处调用本来就没有retrievedContext字段，没有删除原有检索知识路径。

单元测试核验两个provider返回一致、模型fetch未调用、参考材料及生成的掌握摘要不进入指令；同实际输入的最后任务测试也通过且记录零HTTP请求。此环节无模型耗时，不能将之前1.413秒模型测量作为最终实现的时延。

同一浏览器报告HTTP耗时79.803秒，provider耗时77.766秒、重试一次。原high报告五维全100，且将已明确修正的“只有沸腾才蒸发”以巩固为由再次作为OPEN漏洞。此旧输出不能解释为学生仍持有该误解。

报告的三个方案：保留high并仅改等待提示；在相同输入上比较low并保留全部证据门禁；异步生成并在HTML显示任务状态。本轮先验证第二种，第一种不能解决已观测的报告耗时，第三种涉及更广工作流，未实施。

第一批仅在测试fetcher覆盖low的两次报告分别20.712/20.049秒、零重试，Zod与原文引证门禁均通过；但分别制造了超出目标的微观机制缺口、忽略后文的汽化术语缺口，五维分数也明显波动，不能只凭速度就判质量通过。后续窄修要求按时间顺序核对后续修正，gaps只列当前目标内未补齐的缺口，巩固放nextSteps；另保留五维引用、服务端平均分和全部输出校验。

最终同输入两次low报告为 **37.239秒（一次输出校验纠偏）与18.257秒（零重试）**，均返回`gaps=[]`，不再将已修正错误或超范围巩固任务制造为OPEN漏洞。两次五维引文均通过原有服务器校验；这里没有把降低推理预算等同于降低证据门禁。生产仅为report选择low，仍开启推理、保留原有输出预算及有界重试，其他操作的推理档位未被统一下调。

最后报告一次仍发生输出拒绝，实验保留了该调用及重试耗时，没有保存首份被拒报告全文，故不进一步认定其具体引文错误。37.239/18.257秒与原77.766秒provider观测有改善，但样本很小，模型、缓存及重试会影响时延。全100分的最终输出也不等于通过教师评分校准，不外推分数稳定性。

证据：`.data/coaching-live/report-performance-2026-11-04T16-20-50-403Z.json`、`.data/coaching-live/report-performance-2026-11-04T16-24-21-426Z.json`、`.data/coaching-live/report-performance-2026-11-04T16-29-59-630Z.json`（最终中性费曼指令，requests为空）；实际导出输入 `.data/improvements-20261104/completed-live-provider-input.json`（合成会话，无账号凭据）；测试 `tests/smoke/report-performance-live.test.ts`。测试需同时设置 `RUN_DEEPSEEK_LIVE_TEST=true`、`RUN_REPORT_PERFORMANCE_TEST=true` 及指向合成输入的 `REPORT_PERFORMANCE_INPUT_PATH`，不在默认测试中消耗真实模型。
