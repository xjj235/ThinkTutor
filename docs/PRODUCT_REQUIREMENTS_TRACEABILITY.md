# ThinkTutor 原始项目说明书需求追踪

需求来源：`D:\桌面\数据实现\问思学伴项目说明书.md`。本文将原始教育产品意图映射到当前真实实现。后续生产升级计划可以增加安全、用户、课程、运维能力，但不能改变“教师主导、学生主体、AI 辅助”及“输入—建构—输出—反馈”的核心定位。

## 判断规则

- 原始说明书定义产品为什么存在、服务谁以及核心学习体验；
- `docs/PLAN.md` 定义当前产品边界和交付阶段；
- `docs/ARCHITECTURE.md`、`SECURITY.md` 和 `PRIVACY_DATA_FLOW.md` 定义安全实现约束；
- 功能必须通过浏览器 HTML 完成，API 或 CLI 本身不等于产品完成；
- 计划中的宽泛描述必须转化为可授权、可验证、不过度推断的具体功能；
- 与隐私、权限、证据真实性冲突时，优先采用更严格的服务端边界。

## 谨慎完善原则

1. AI 不代替教师提供完整标准答案；
2. 学生课程材料必须来自其已获授权的课程范围；
3. 学习报告只依据实际对话证据，不升级为正式成绩、人格或心理判断；
4. 教师分析只展示教学所需最小信息，不开放跨课程、跨班级数据；
5. 阿里云承担 HTTPS、网络隔离、可靠存储和访问控制，但不能替代业务权限与隐私治理；
6. 真实 DeepSeek、RDS、Tair、OSS、域名、证书、备案和法律审核未验证前，不能宣称已生产上线。

## 主动推演与验证方法

当说明书没有规定交互细节时，可以主动提出并实现合理方案，但必须按以下顺序验证：

1. 先明确该推测解决的真实用户问题；
2. 同时推演正常操作、误操作、恶意篡改、并发重试、移动端和生产网络场景；
3. 安全与数据判断放在服务端，HTML 只负责展示和提交；
4. 使用数据库关联、Zod、RBAC、事务或幂等机制形成可证明的边界；
5. 增加正常路径和反向路径测试，不能只证明按钮能点击；
6. 本地 Mock 验证通过后，再把真实云资源列入人工上线验收；
7. 若推测会改变核心教育角色、数据用途或产品范围，必须停止扩展并回到原始说明书核对。
