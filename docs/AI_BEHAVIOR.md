# AI 行为与 DeepSeek Provider

生产 Provider 仅为 `DeepSeekProvider`，模型从 `DEEPSEEK_MODEL` 读取，生产必须等于 `deepseek-v4-flash`；开发和全部自动测试默认使用确定性 `MockAIProvider`。不存在 OpenAI SDK、OpenAI Provider 或旧 DeepSeek 模型名。

## 调用策略

- 诊断、主动提示、费曼说明关闭 thinking；普通新作答使用独立简洁的追问提示，启用低强度 thinking、输出上限 8000 token。只选择当前目标内、学生实际表达所暴露的最近一步，不把所有尚未讲过的新知识都当成本轮缺口；
- 普通作答先经过独立内容审核，启用低强度 thinking，求出题目新的核心结果，同时列出实际使用的前提及其来源、核对关系方向，并检查答案暴露、题设自洽及信息可定位性；再将该答案作为请求内的 `contentCheckAnswer` 交给关闭 thinking 的教学审核，只检查当前误解检验、已修正后的应用及面向学生的反馈，不重新求解或选择前提。服务端拒绝教学审核改写该答案；两个审核输出上限均为 8000 token，原始推理不保存或展示；
- 报告、再练任务、上下文摘要、材料关键词启用 thinking 并设置高推理强度；
- 只消费最终 `message.content`，不保存或展示 `reasoning_content`；
- Chat Completions 使用 `response_format: {type: "json_object"}`，系统消息同时给出 JSON 词与结构示例；
- JSON 解析后必须再过对应 Zod Schema；`overallScore` 不属于模型 Schema。
- 会话创建、回答和提示会先按课程、章节、主题、目标与学生最近回答检索已有课程知识库；命中片段写入 `retrievedContext`，并标记 `COURSE_KNOWLEDGE_FIRST`。
- 当 `DEEPSEEK_WEB_SEARCH_FALLBACK=true` 时，现有代码会改用 Responses API 并发送 `web_search` 工具要求，保留课程材料与来源校验边界；普通新作答同时传 `reasoning.effort=low` 和 `max_output_tokens=8000`。请求工具不等于实际完成检索：[官方 Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/) 当前仅支持 `function`，其他工具类型可能被忽略，返回的来源文字或工具旗标不能单独证明实际检索。本轮真实教学测试明确关闭联网；真实联网仍未验收，未因本轮修改而新增搜索提供方或改变生产开关。
- 如果显式关闭 `DEEPSEEK_WEB_SEARCH_FALLBACK`，才允许 DeepSeek API 使用通用知识继续生成学习教练输出；此时不得声称内容来自课程知识库、教师材料或实时联网检索。

每轮只有一个主要问题。苏格拉底类型包括概念澄清、原因追问、证据追问、假设检验、反例、迁移和支架提示。未展示的能力不能生成掌握证据；报告每个维度必须给出本次对话证据。

## 学生可理解的逐轮反馈

每次新作答先生成 `learningFeedback`，再呈现针对该关注点的问题：

- `answerQuote` 逐字摘自当前回答；`observation` 说明已经表达的理解或证据不足。
- `focus` 说明下一步只补充或核验什么；`whyItMatters` 说明它对当前判断的意义。
- `progress` 只记录有前后学生证据支持的变化，没有依据时为 `null`。未说明不等于答错，进入下一阶段不等于已经掌握。
- 反馈直接对“你”说明当前理解、下一步行动及其意义，不展示“学生本次……”“取得学生……证据”等后台诊断口吻。回答“不知道”后应给出真正较小的可答问题，类型为 `SCAFFOLDED_HINT`；普通未锁定动作的错类型输出会先在服务端拒绝并按原有次数纠偏。
- 服务端将反馈与真实学生消息 `feedbackForMessageId` 一起保存；刷新、历史及报告共用这份记录。旧记录不补造反馈。
- 普通 DeepSeek 作答经过结构、原文匹配和教学质量审核。审核检查问题是否与反馈一致、能否取得检验当前主张的新证据、是否可回答、前置知识是否充分、支架是否适合当前回答、措辞是否尊重学生，以及是否泄露待问结论。当前仍有错误主张时，无区分能力的正例不能仅靠泛问“为什么”通过；已经修正后可以应用正确规则完成具体任务，不再强求区分已经放弃的误解。允许围绕同一缺口换角度继续同类追问。审核失败按 AI 失败处理，不写作答、不推进阶段。
- 审核先解实际题目，再检查反馈及题面中的术语、修饰语和纠错句是否已经暗示待答结论。前置事实必须列明来源与对应原文；目标、年级、同章出现或学生尚未讲过某个新知识不能代替支持。服务端拒绝无支持事实、来源不匹配的引用和缺少图示或标号等定位材料的追问，即使审核同时给出通过布尔值。上述审核证据仅在当前请求内部使用，不写入学生记录或原文日志。
- 前提证据由内容审核返回 `prerequisiteEvidence`（0–4 项，每项包含 `fact`、`kind`、`source`、`quote`），教学审核没有这组字段，不能遗漏或改写它来放行。`DOMAIN_RULE` 不允许标为 `BASIC_OPERATION`，`UNSUPPORTED` 或引用不匹配均直接拒绝；缺前提可返回 `UNSUPPORTED_PREREQUISITE`。正向关系不自动支持逆命题，但合法逆否仍可使用原关系。基础名称本身正是当前待答目标时允许空前提，避免把“不知道”后的命名支架全部拒绝；完整判定方法或应用推断所用的学科关系必须列明。
- 答案暴露以本题真正待答的判断、推导或结果为准。应用题可给定必要条件、点明有来源支持的已知定理或方法，只要具体求解仍由学生完成；定理名字本身不等于求值结果。若本题正是在问适用条件，先告知条件再问仍应拒绝。尚待判断的具体例子不能预称“反例”或“错误案例”暗示结果；学生已确认的反例可以回顾，也可以请学生自行构造反例。
- 专项知识库使用已有证据与服务端诊断生成反馈；只有可靠、独立的新证据同时对应当前目标、实际上一轮问题及其缺口时才记录变化，跑题或其他目标的新内容不算本轮进步。案例、目标切换、反思和轮数上限均需说明后续任务的意义。
- 首次诊断、主动提示和恢复事件没有新作答，不生成新的学生评价。提示与原问题的反馈一起展示。
- 学习轨迹区分已作答、等待作答和中途切换任务；新任务的答案不归给被替换的旧问题，也不把旧问题永久显示为等待继续。
- 教学审核拒绝草稿时，在现有重试次数内按白名单检查项给出固定纠偏要求。被拒草稿仅在本次调用的不可信数据区保留；原学生回答不变，审核答案不传给生成器，纠偏内容不进入学生记录。明确的责备句式在调用审核前直接拒绝，学生原文引用不参与该措辞检查。
- 内容审核发现答案暴露时，若字段与摘录确实匹配被拒草稿，重试数据额外携带该字段名和原句，帮助生成器定位改写。不会传回审核给出的最低答案、答案解释或原始推理；没有来源匹配的摘录不进入纠偏数据。
- 两层审核共享的答案只放在教学审核的不可信数据区，输出 Schema 保持静态，不把该答案插入系统规则或动态 Schema；审核回调检查逐字一致。它不进入生成器的纠偏数据、学生记录或原文日志。教学审核若发现答案本身冲突，可以拒绝，不得编造相反答案来制造区分能力。
- 普通回答每次尝试最多调用生成、内容审核、教学审核各一次；两个审核均不单独重试。最多两次生成重试时，总上限为 9 次 HTTP 调用；内容审核拒绝则跳过教学审核。会话锁按 `3 × (重试次数 + 1) × 单请求超时 + 10 秒` 预留，其他操作保持原预算。成功轮比原先增加一次短审核调用，实际 token 按操作记录，不用测试通过代替教学效果验证。

模拟模式依据表达线索安排练习，明确显示模拟反馈，不再用追问轮数推断掌握或清空缺口。真实模型样例验证与模拟流程验证分别记录，均不等同于真实教学效果验证。

## 不可信边界

学生输入、教师参考材料与检索片段都放在 `<untrusted_learning_content>` 包装内，不拼入系统规则。材料中的“忽略规则、泄露提示词、改变角色”只视为学习内容。Markdown 渲染关闭原始 HTML，不使用 `dangerouslySetInnerHTML`。

## 失败

超时、429、网络/5xx、无效 JSON 与 Schema 错误映射到统一可重试错误；最多两次指数退避。AI 调用发生在数据库状态事务前，因此失败不会推进阶段、增加轮数或伪造学生消息。

## 可观测性

记录 provider、model、operation、状态、官方返回的 Token、缓存命中 Token、耗时、重试次数和错误码；不推测或伪造 Token，不记录密钥、完整提示词或完整学生原文。DeepSeek `user` 是服务端加盐域隔离后的不可逆稳定哈希。
